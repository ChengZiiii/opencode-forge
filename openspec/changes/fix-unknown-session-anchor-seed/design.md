# Design: fix-unknown-session-anchor-seed

动机见 proposal.md（Why）。这里只写怎么做，以及为什么这样做而不是那样做。
**草案，未批准，未动代码。**

## Context

- **模块状态按宿主进程共享一份**（arm1 结论：“shared module”——B 目录初始化后，
  S 仍绑在 A）。`sessions` 表、`hostWorktree` 都在这份共享状态里。
- `hostWorktree` 由 `v2Setup` 在**每次**目录初始化时赋值为该目录
  （`plugin.ts` L10431–10432），所以多目录宿主上它就是“最后初始化的那个”；
  目录被驱逐时不清。
- **工具体**的解析顺序（`v2ToolContext`，L9047，0.33.1 修的）：事件自带目录 →
  内存绑定 → 宿主会话记录（`hostSessionDirectory`，L9021：经注册初始化自己的
  客户端，自身目录 → 父链，最多 8 层）→ 默认目录（带提示）。
- **检查**走的是另一条：`stateForBan(sessionID)`（L6789，同步）——内存表里
  没有就拿 `hostWorktree` 建绑定。调用点：
  - v2 执行前接缝：草稿禁写（L9328 → `draftDispatchRefusal` L9334）、状态文件
    边界的基准目录（L9316–9317）；
  - v2 权限评估接缝：草稿禁写（L9212–9219，原地改 `evalInput.effect`）；
  - 插件 `task` 工具体里那次检查（L5426），排在“按宿主记录重绑”（L5465）
    **之前**；`crew_begin` 工具体里的“草稿期禁止 crew 编排”（L6393）；
  - 派发泵 / 重试 / 恢复路径的三处（L3618、L4079、L5050，经
    `draftDispatchRefusal`，都在 async 上下文里）；
  - `governingGoalFor`（L844，同步）、v1 拦截带（L8041–8067、L8434）。
- **空闲续跑路径不依赖播种**：空闲边沿在查目标之前先按宿主记录懒绑定
  （L7361–7380：`client.session.get` → `ensureSession`），所以去掉播种不会
  让 goal 续跑漏掉。
- **时序事实**（探针，2026-11-24T13:47Z）：宿主 2.4.0 上，同一次工具调用
  **执行前钩子先于权限评估触发**（13:47:13.741 `v2-before` → .744
  `v2-evaluate`）；执行前接缝抛出的拒绝确实生效（arm7 对照）。

## Goals / Non-Goals

**Goals**

- 凡是依赖会话目录的检查，都按会话**自己的**工作区裁决，不按最后初始化的目录。
- 单目录宿主（v1 与 v2）逐字节不变。
- 查不到就保持未绑定、放行，绝不猜。

**Non-Goals**

- 会话创建时不绑定（宿主 2.4.0 上 `session.created` 不带来绑定，原因未查）。
- 原生 `subagent` 派发不过插件的门——另一个 change
  （`gate-native-subagent-dispatch`）。
- `hostWorktree` 与会话绑定无关的用法：`forge_shell` 姿态配置（L2247）、
  dispose 时按它恢复 / 收养派发（L10731–10743）。
- `v2ToolContext` 的解析顺序、默认目录兜底及其提示、空闲时的懒绑定。

## Decisions

### D1 “本进程初始化过几个目录”是播种与否的唯一开关

`v2Setup` 里记一个模块级的集合：本进程初始化过哪些目录（规范化后、非根的
锚点，就是现在喂给 `hostWorktree` 的那个值）。`stateForBan` 只在集合大小
≤ 1 时保留“拿启动目录播种”。

- **驱逐不收缩集合。** 这一代宿主的驱逐信号不可靠（`location.shutdown` 不发；
  健康 location 被驱逐时 `build.close` 不执行）。所以一个进程只要初始化过
  第二个目录，就按多目录处理到进程结束。
- **v1**：`v2Setup` 从不运行，集合为空，播种照旧——逐字节等价。
- **单目录 v2**：集合一项，播种照旧。

备选：①按“当前已加载”维护集合、随驱逐增减——依赖不可靠信号，否决。
②只记一个布尔、第二次初始化时翻——等价；用集合是为了测试面与诊断能直接
读出“哪几个目录”。

### D2 `stateForBan` 在多目录进程上不再播种；新增异步解析器喂给能读宿主记录的接缝

- `stateForBan(sessionID)`：签名不变。返回已知状态；只在 D1 判定单目录时
  播种；多目录进程上的未知会话返回 `null`。
- 新增 `stateForCheck(sessionID, client)`（async）：已知状态直接返回；
  多目录进程上的未知会话 → `hostSessionDirectory(client, sessionID)` →
  查到就 `ensureSession(sessionID, 目录)`（与工具体同一条写入路径，台账
  证据也一样），查不到返回 `null`。
- **改用它的接缝**：v2 执行前接缝（草稿禁写、状态文件边界）、插件 `task`
  工具体、`crew_begin` 工具体（L6393——只去掉播种会让它从“查错目录”变成
  “不查”，把误拒换成漏拒）、派发泵 / 重试 / 恢复路径的三处。它们本来就在
  async 上下文里。
- **保持同步的调用方**：`governingGoalFor`（L844）在多目录进程上对未知会话
  返回 false——落向保守的一侧（crew 待定暂停照常生效、关停照常走 ask）；
  会话一经懒绑定或任何工具体调用就已知。v1 拦截带不变。
- `draftDispatchRefusal(sessionID, target)` 保留签名给 v1 拦截带，抽出
  “按状态裁决”的核心；异步调用方先解析状态再裁决。
- **权限评估接缝保持同步查找**，只是不再播种。它靠原地改 `evalInput.effect`
  生效，宿主是否等一个 async 钩子改完再读，没有证据——所以不引入 `await`。
  多目录宿主上它对未知会话不再提前拒一次；执行前接缝先触发（已观测），是
  权威的那道门。这一条必须有沙箱腿钉住：会话自己目录里有草稿时，端到端
  仍然被拒。
- **用哪个客户端**：接缝闭包自己的 `anchorClient`——注册它的那次初始化交
  进来的、与它的工具体共用的那个；绝不用模块级的“最后一次初始化”。共享
  模块上每个目录的初始化各注册了一个闭包，谁先跑到谁解析；宿主会话记录是
  宿主全局的，每个客户端读到的都一样。

备选（乙，更小）：只做 D1、接缝不查宿主记录。多目录宿主上的未知会话在
工具体或空闲懒绑定绑定它之前完全不设防——重启后第一次写不受草稿禁写
约束。把“拒错”换成“漏拒”，不作默认；D2 的沙箱腿出问题时再退到它。

### D3 状态文件边界的基准目录

L9317 的 `state?.worktree ?? hostWorktree ?? ""`：多目录进程上改为
`state?.worktree ?? ""`。没有基准时，绝对路径照常检查，相对路径不拿任何
别的目录去拼（放行）。单目录与 v1 不变。

### D4 插件 `task` 工具体的检查顺序

工具体自己的检查（L5397–5426）排在“按宿主记录重绑”（L5465）之前。改为
先经 `stateForCheck` 解析（用它本来就用于重绑的那个客户端），再检查——
被拒的派发只可能让调用者绑到自己的目录。

### D5 绑定证据

`stateForCheck` 写绑定走 `ensureSession` → `noteSessionAnchorLedgerBinding`
（只对拥有池文件的目录记账，每个（会话，目录）对每宿主生命周期一次）。
沙箱复现臂断言的就是台账里这些行。

## Risks / Trade-offs

- [权限评估接缝对多目录宿主上的未知会话不再提前拒] → 执行前接缝先触发并
  裁决；沙箱腿验证“自己目录的草稿、重启后”端到端仍被拒。
- [宿主记录读不到时，那次调用的草稿禁写被跳过] → “未知会话失败放行”是
  既有姿态（`tool-partition`）；下一次工具体调用会按宿主记录绑定，之后禁写
  生效；锚点探针能看到未绑定这一步。
- [初始化过两个目录的宿主永久失去播种] → 改走宿主记录，本来就是更准的
  来源；解析不了的会话是“未绑定”而不是“绑错”。
- [`governingGoalFor` 对多目录进程上的未知会话返回 false] → 保守方向：crew
  待定暂停照常生效；空闲懒绑定先于目标检查，续跑不受影响；既有的 goal
  续跑测试保持绿。
- [每个目录初始化注册的闭包都会被触发] → 第一个绑定，后面的命中内存表，
  不多读宿主。
- [`plan-harness` “重启后禁写不再自动生效”与现行实现对不上] → 既有张力，
  本 change 不改单目录行为；已在 proposal 里提给用户。
- [多一次宿主读取] → 只对模块不认识的会话读一次（最多 8 层），之后命中
  内存绑定。

## Migration Plan

排在 0.34.1 之后，作为 0.34.2 发布。无配置项、无数据迁移、无文件格式变化
（台账行是普通行）。回滚 = 装回上一版。
