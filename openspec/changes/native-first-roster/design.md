# native-first-roster — design

## Probe anchors (2.3.2 sandbox, 2026-11-21)

`reports/probe-native-agent-surface.md` — ten-item matrix, five shaping
facts: (1) no first-class depth key; unknown frontmatter keys pass
through to request.body UNLESS `permissions` is present, which flips
unknown keys to WARN+drop — the compiler therefore emits ONLY
probe-proven keys; (2) `tools:{...}` face works but vocabulary drifted:
shell channel is `execute`, dispatch tool's real name is `subagent`
(`task:false` maps to it); (3) missing `mode: subagent` makes task
dispatch silently fall back to general — the single nastiest hand-writer
trap; (4) scoping is up-tree merge, same-name cross-layer = scalar
project-wins + global permissions spliced, no collision protection;
(5) `/api/config` never shows native agents — roster queries go through
`GET /api/agent?location[directory]=`.

## Decisions

- **D1 — Recipe stays the semantic center.** Pools, session-domain
  dispatch gating, crew roster disclosure, compliance checks keep
  reading forge.json through the existing pool resolver — zero gate
  rewrites, zero semantic change to orchestration. Native md files are
  a compiled projection, never an authority.
- **D2 — Compiler output contract.** Pure core
  (`src/roster-compile.ts`, no @opencode-ai imports, injectable fs):
  recipe → file set. Destinations by family: workspace pools → the
  workspace's `.opencode/agent/`; the global fallback family → the
  host's own global agent dir `<home>/.config/opencode/agent/` (owner
  decision 2026-11-21, ISSUE-2 = accept + document: semantically exact
  — the host's global agent dir IS the native equivalent of our global
  roster; the write never happens on machines without a global recipe;
  load-bearing — the crew gate on global-only hosts heals only when
  sync lands there). Per entry: `.opencode/agent/forge-<ns>-<id>.md`;
  frontmatter = description (provenance: pool + source path, as today),
  `mode: "subagent"` (always), `model: "provider/model[#variant]"`,
  `tools` face per shape in probe-vocabulary (readonly shape: the
  MUTATING_TOOLS family + `execute` false; write shape: `subagent`
  false, shell face handed to the forge_shell partition which stays
  name-keyed on the `forge-` prefix); prompt body = dispatch mandates +
  shape frame + role prompt (compile-time baking replaces runtime
  injection for native workers). Header comment: GENERATED BY
  forge_sync — edit the recipe, not this file.
- **D3 — Depth: variant-first, dictionary via params.** Recipe words
  that map to variant values (`low|medium|high`) compile into the model
  string; the rest (none/minimal/xhigh/max, budget translations) ride
  the existing chat.params name-keyed injection — public API, disclosed
  per spawn. The 7-word dictionary and translation matrix are untouched.
- **D4 — Staleness gate + agent-layer sync.** crew_begin precheck in
  NATIVE mode only (the runtime path keeps its existing checks; there
  is no draft-materialize precheck): recipe mtime > newest matching
  artifact mtime triggers a **content adjudication** — if every
  compiled artifact byte-matches what the current recipe compiles to,
  the verdict is fresh (a touch or clock skew with no real change must
  not deadlock the gate); any difference → refuse with the one-step
  fix. The same staleness hint covers the plain dispatch path — on
  native mode a task dispatch against an empty native roster with a
  non-empty recipe surfaces the same sync guidance (a fresh workspace
  after upgrade must not dead-end at "worker not found"). `forge_sync`
  is a registered tool the forge agent calls in-band
  (transcript-visible), atomic writes (temp+rename, best-effort temp
  cleanup on failure), GC removes orphaned `forge-<ns>-*` files for
  entries deleted from the recipe (mirror of "删池文件即失池").
  Hot-apply picks up changes without restart (probe PASS).
  `sync:"auto"` opt-in: regenerate on detection at session start,
  disclosed via finding (setup-time console warn — no session findings
  channel exists that early; accepted channel downgrade, recorded).
- **D5 — Migration knob.** `materialize: "native" | "runtime"`: the knob
  defaults BY HOST GENERATION — v1 hosts pin "runtime" (native agent
  files are a v2 host facility; v1 behavior stays byte-equal forever),
  and **v2 hosts default DIRECTLY to "native"** (owner decision
  2026-11-21: no deprecation window — the v2 experience is strictly
  better and v1 is unaffected by generation pinning). "runtime" remains
  selectable on v2 as an escape hatch. Both modes coexist safely
  because the pool resolver is shared; existing workspaces with a
  recipe and no artifacts read as "stale" and are healed by one in-band
  sync — no workspace-file migration ever.
- **D6 — Vocabulary drift is a first-class risk.** The host already
  renamed bash→execute and task→subagent within one minor era. Compiler
  emits from a single `NATIVE_TOOL_VOCAB` constant; a drift-mirror test
  locks the constant to the probe evidence; handbook documents the
  current names with a "host vocabulary may drift — forge_sync
  re-emits" note.

## Non-goals

No orchestration internals changes; no silent plugin writes by default;
no host-layering fixes; no new depth semantics.

## Test plan

- Compiler: recipe → file set matrix (namespacing, mode stamping,
  variant mapping, tools vocabulary, mandate baking, header, GC).
- Staleness: gate refuses stale, passes fresh; sync tool round-trips
  (write → gate clears); atomicity (no partial file survives a failed
  write).
- Depth: variant words compile into model strings; non-variant words
  keep the params path (existing depth tests stay green).
- Migration: knob matrix — runtime mode byte-equal to today (existing
  788 baseline is the regression net), native mode pure additions.
- Handbook: README renders; recipe cookbook examples validate against
  the schema.
