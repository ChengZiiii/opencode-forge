### 老账 D1 是什么、三个选项

清作业的那段代码挂在 v1 入口的 `dispose` 钩子上，而宿主 2.4.0 的 v2 加载器只读
`default.id` 和 `default.setup|effect`、从不调用 v1 钩子，所以那段代码在 v2 宿主上
**永远执行不到**。驱逐目录实际上不会杀任何作业（对在飞的派发是安全的），但规格和
代码注释描述的那个触发条件并不存在。验收门把这条腿记成“记账”，而判“通过”时只看
失败和缺失——所以 0.33.0、0.33.1、0.34.0、0.34.1 四版都带着同一笔账过了门。

> **更正（2026-11-25）**：这一段原先写的是“宿主 2.4.0 只把 `setup` 返回的函数当
> 清理函数，所以……永远执行不到”。**机制写错了**：v2 的清理函数（`v2Setup` 末尾
> 那个）在 2.4.0 上是会被调用的，只是它本来就不碰任何作业；执行不到的是 v1 的
> `dispose` 钩子。现象、结论、三个选项都不变。

- 甲：把 v2 的清理接到同一个作业清理函数上。要先解决两个隐患：它会连作业
  围栏一起结束；模块级单例被两份激活共享。

## 备注：今晚测试基础设施踩的坑（都会让结论失真）

0.33.0 那一批（9 条）记在 `docs/overnight-2026-11-23-runbook.md`。之后新增：

1. 2.4.0 的工具部件里没有时间字段——完成看 `status`，计时只能用消息行的时间。
2. `forge_shell` 走 PowerShell，`>nul` 会立刻失败且退出码是 0——“保持忙”的块
   必须用 `Start-Sleep`。
3. 等待不能依赖“会话空闲”：旧构建上 15 秒一条的通知会不断给空闲会话开新回合。
4. `Start-Process -ArgumentList` 里带空格的参数必须整段加引号，否则被拆开。
5. node:test 默认没有单测超时，挂住的用例会让整份文件永不结束。
6. 沙箱宿主的内建代理 id 是小写（`general` / `build` / `explore` / `plan`），
   `/api/agent` 列的是显示名。
7. 读正在被宿主追加的日志用 `read` 工具或 node，.NET 默认的共享方式会撞锁。
8. 沙箱脚本 `sbx-link.mjs show` 报的 `bytes=` 不是字节数（哈希是对的）——已实测坐实：
   那一行打印的是解码后的字符数（`dist/index.js` 实际 963253 字节、946735 字符），
   是脚本把标签写错了，文件没问题；标签还没改。
   `sbx-restart status` 读的是 main 的 dist；`--version` 开关会往真机日志里写；
   `probe-real-locations.mjs` 的引导里漏了 `.opencode\goal`。
9. 本机的宿主源码检出不是 2.4.0 标签，而是标签之前 73 个提交的版本。读宿主源码
   一律用 v2.4.0 标签的完整镜像（`research\tag-2.4.0\full\`）。
10. 插件的 `task` 认代理 id 时区分大小写、要精确匹配：传显示名（`General`）会
    得到 `Agent not found`。沙箱宿主代理清单里 id 是小写、显示名首字母大写。
11. “我看自己的工具表”不能当证据：它呈现出来的样子和宿主源码不是逐字相同。
    宿主到底给没给某个工具，只能实际调一次来验证。
12. 不走代码模式的工具（比如原生 `subagent`）不会出现在代码模式的目录里；在
    目录里搜不到，不等于没有。
13. PowerShell 5.1 的 `Get-Content` / `ConvertFrom-Json` 读不带 BOM 的 UTF-8 文件
    会按系统默认编码读，含中文或省略号的 JSON 会解析失败。读这类文件用 node，
    或显式指定编码。
14. 通过代码模式创建定时任务时，代码是作为字符串传进去的——里面不要出现反斜杠
    （路径用正斜杠，换行用 `String.fromCharCode(10)`），否则会多转义一层。创建前
    先对着真实输出内联试跑一遍。
15. 驱动的“通过”必须以“场景成立”为前提（例如驱逐那一刻派发确实在飞）。前提
    不成立要单独标出来并自动重试：不能记成产品的失败，更不能记成通过。
16. 同一批调用里，不要把“写文件”和“读或运行这个文件”放在一起——读到的是
    旧内容。
17. 联接切换（`sbx-link`）不会重启宿主：驱动读的构建指纹取自联接当前指向的
    产物，所以跑驱动前必须让联接指向宿主实际加载的那份构建。
18. 压缩摘要里回放的旧工具调用，是按 JSON 再转义过一层显示的，照抄会多转义一层。
    工具参数按原样写（一层转义即可）；拿不准就先放一个探针（JS 里 `'a\\b'` 的长度
    应为 3）。另外 `[IO.File]::ReadAllText` 读正在被追加的日志会撞锁，和第 7 条
    是同一回事。
19. 空输出不是结论。同一条命令前几次有输出、后几次没有，先怀疑自己改坏了什么，
    换一种读法（node）确认了，再下判断。
20. 宿主会话 id 的前 12 位十六进制，是“（毫秒时间戳 × 4096 + 计数器）按位取反”
    后的低 48 位（`packages/schema/src/identifier.ts`），可以解出会话的创建时刻。
21. “插件能不能调到某个宿主接口”要以插件适配层（`plugin/src/promise/adapter.ts`）
    为准——它是挑过的。宿主客户端有的接口，插件不一定有（作业接口就是例子）。
22. 一个文件里混着两件事、要分两笔提交时，不要用零上下文补丁只暂存一部分改动块：
    纯插入的块没有上下文可对齐，git 会把它落在补丁的“新文件”行号上，位置可能差
    一截（这次差了 17 行）。做法：整文件暂存，再把不属于这一笔的块**反向**从暂存区
    打掉，然后拿独立重建的内容比对哈希。这次的错就是被这一步拦在提交之前的。
23. 对着 diff 的加减行下判断不可靠：相邻的几段会交错显示，把两段话看成一段、把 v1
    入口的代码当成 v2 的，都是这么来的。要下判断，读文件本身，并先确认那段代码在哪
    个函数里。另外内联命令里的正则不要带反斜杠（又中了一次），这类判断写进脚本。
24. 经典控制台窗口（conhost）在后台收不到整段文本投递——驱动回了“成功”，字符却没落进
    输入框。控制台窗口只能逐键发，并且每次提交前从截图读回输入框。
25. TUI 的 `/new` 只开一个空标签页，会话要等第一条消息发出去才创建。找会话的脚本必须在
    那之后才挂得上；它写下的说明行里“由 /new 创建”的说法不准。
26. 看门脚本比窗口先结束，窗口关之前那一段就没有看门。补救是事后直接问宿主：所有会话现在
    有没有挂起的确认请求、在不在忙（没人再回答，挂起的请求会一直挂着，问得到）。
27. 证据文字里“屏幕上看到的”只能照当时的流水账转录；从上一版证据里沿用的句子要先对账。
    这次初稿里有 8 处说法是记录撑不住的（见“作废与失误留痕”二十一）。
28. PowerShell 5.1 的 `>` 重定向写出的是 UTF-16 文件，读文件的工具会把它当二进制拒读；
    要存 UTF-8 用 `[IO.File]::WriteAllText`。`| Select-Object -First N` 会提前掐断上游
    进程，`$LASTEXITCODE` 变成 -1——要退出码就别截管道，输出写进文件再看。
29. 复杂一点的判断写进脚本文件再跑。内联的 `node -e` 要经 PowerShell 和代码模式两层
    转义，正则里的反斜杠和 `\r` 这类转义都会被改坏（这一轮又中了两次，都是报错或空输出，
    没有因此得出错误结论）。
30. `.cmd.txt` 这种文件名不能把全路径交给 `cmd /c`——Windows 按扩展名用记事本打开它。
    要运行先复制成 `.cmd`，并且批处理内容必须纯 ASCII（一个非 ASCII 字符就会让 cmd 把
    那一行读歪）。
31. 在工具报错这类文本里找“带引号的原文”，要先把 JSON 转义去掉再比：孩子照抄报错时
    引号是 `\"`，按原文精确匹配会落空（深度探针两次误判）。比对前还要把对象形式的
    报错（`{shape, text}`）转成字符串——它会让 `includes` 直接抛错。
32. 在新目录里复制池文件做探针时别换池名：编译出来的代理名带着池名
    （`forge-<池>-<角色>`），换了名字就找不到工人；而且只有池文件不够，要先跑一次
    `forge_sync` 工人代理才会生成。每建一个临时目录，沙箱宿主里就多一个“已删除但仍
    加载”的位置——能让已有目录回答的问题，别新开目录。
33. `edit` 工具的参数里必须带 `path`——这一轮又漏了三次（都报错，没改坏东西）。整份
    重写的文件，写完用 git 把“被删掉的行”全列出来对一遍（`doc-diff-check.mjs`），
    没有意料之外的删除才算数。
